# 운영 안내 — 무료 한도, 사용량 점검, 백업·복구

## 1. 무료로 운영하는 구조

| 부분 | 어디서 | 비용 |
|---|---|---|
| 앱 화면(HTML·JS) | Render Static Site | 무료(대역폭·빌드 시간 한도 안에서) |
| 자료·개념·카드·시험·통계 | 사용자 브라우저 IndexedDB | 없음(서버에 저장하지 않음) |
| PDF 해석·개념 추출·채점 | 사용자 브라우저 | 없음(AI API 호출 없음) |
| 친구 광장(실시간) | Render Free Web Service | 무료(월 750 인스턴스 시간 안에서) |

광고·결제 기능은 없고, 비용이 생기는 기능을 자동으로 켜지 않습니다.

## 2. Render 무료 한도와 주의사항(2026년 11월 확인)

- **Free Web Service는 15분 동안 요청이 없으면 잠들고**, 다음 요청 때 깨어나는 데 약 1분 걸립니다. 친구 광장에 처음 들어갈 때 “서버 확인 중”이 오래 걸리는 이유입니다.
- 워크스페이스마다 **월 750 Free 인스턴스 시간**이 주어지고, 잠든 동안은 차감되지 않습니다. 다 쓰면 그달은 서버가 멈춥니다(개인 학습 기능은 영향 없음).
- 서버를 깨워 두려고 주기적으로 요청을 보내는 기능은 **일부러 넣지 않았습니다.** 24시간 깨워 두면 한 달 시간을 거의 다 써 버립니다.
- **대역폭과 빌드 시간은 워크스페이스 플랜의 포함량**에서 차감됩니다. 최근 Hobby 플랜의 포함 대역폭이 크게 줄었다는 보고(월 5GB 수준, 초과분 과금)가 있으니, 정확한 값은 Render 요금 페이지와 대시보드에서 직접 확인하세요.
  - 이 앱은 첫 방문 때 오프라인용 파일을 한꺼번에 받아 두며, 압축 전송 기준 약 1~2MB입니다. 이후 방문은 캐시를 쓰므로 거의 전송하지 않습니다.
  - 결제 수단을 등록하지 않으면 초과 과금이 발생할 수 없고 한도에 도달하면 서비스가 제한됩니다. **결제 수단을 등록했다면** 대시보드의 사용량 알림을 꼭 켜 두세요.
- 무료 서버의 파일 시스템은 재시작 때 사라지므로 **영구 저장소로 쓰지 않습니다.** 방 정보는 메모리에만 있습니다.

## 3. 사용량 점검 방법

1. Render 대시보드 → 워크스페이스 **Billing / Usage**: 대역폭, 빌드 분, Free 인스턴스 시간.
2. `study-star-server` → **Metrics**: 메모리(512MB 한도), 요청 수.
3. `study-star-server` → **Logs**: 요청 경로·오류만 기록되며 문서 내용·닉네임·토큰은 남기지 않습니다(초대 코드도 `/rooms/:code`로 가려집니다).
4. 서버 `/health`의 `rooms` 값으로 현재 방 수를 볼 수 있습니다. `MAX_ROOMS`(기본 200)를 넘으면 새 방 만들기가 잠시 거절됩니다.

## 4. 서버 보호 장치

- 모든 입력을 Zod로 검증(닉네임 12자, 특수문자 제한, 퀴즈 문항 20개·보기 5개 이하, 요청 본문 64KB 이하)
- IP별 요청 제한: 일반 요청 순간 60회·초당 1회 회복, 방 만들기/입장 분당 약 10회, 없는 초대 코드 시도 10분에 15회(무작위 대입 방지)
- 소켓별 초당 10개 이벤트 제한
- 초대 코드: 암호학적 난수, 헷갈리는 문자(0·O·1·I·L) 제외 6자리(31⁶ ≈ 8.9억 가지)
- 복구 토큰: 32바이트 난수, 서버에는 SHA-256 해시만 보관, 비교는 상수 시간
- 방 최대 4명, 방장 권한(타이머·퀴즈 시작) 확인, 퀴즈 정답은 문항이 끝나기 전 공개 상태에 절대 포함하지 않음
- 같은 문항 중복 제출은 처음 것만 인정(재시도해도 점수가 두 번 오르지 않음)
- 비어 있는 방은 30분 뒤, 모든 방은 24시간 뒤 정리

## 5. 백업과 복구

### 사용자 데이터
- 설정 → **백업 파일 내보내기**: 모든 학습 데이터를 JSON 한 파일로 저장합니다. ‘원본 PDF 포함’을 켜면 PDF도 들어갑니다(파일이 커짐).
- 설정 → **백업 파일 가져오기**: 지금 데이터를 지우지 않고 **합칩니다.** 같은 항목이 다르면 더 최근에 고친 쪽을 남기고, 밀려난 쪽은 ‘충돌 보관함’에 따로 저장해 조용히 사라지지 않게 합니다.
- 예전 형식(백업 버전 1)은 가져올 때 자동으로 현재 형식으로 바뀝니다(`packages/shared/src/backup.ts`).

### 복구의 한계
- 브라우저 데이터 삭제, 시크릿 창 종료, 기기 변경 시 **백업 파일이 없으면 복구할 수 없습니다.** 서버에 사본이 없기 때문입니다.
- 브라우저가 공간이 부족할 때 데이터를 지우지 않도록, 처음 자료를 올릴 때 ‘영구 저장’을 요청합니다(브라우저가 허용하지 않을 수 있음). 설정 화면에서 상태를 볼 수 있습니다.
- 친구 광장의 복구 정보(참가자 ID·토큰)도 브라우저에만 있어, 브라우저 데이터를 지우면 같은 방에 새 참가자로 다시 들어가야 합니다.

### 권장 습관
- 시험 기간에는 일주일에 한 번 백업 파일을 내보내 클라우드 드라이브에 넣어 두세요.
- 다른 기기로 옮길 때: 기존 기기에서 내보내기 → 새 기기에서 가져오기.
